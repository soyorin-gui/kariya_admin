## M1：多环境 Redis 流水查询

### 已确认契约

- Redis Key 为 `yyyy-MM-dd`，每个日期对应一个 List；一次只查询一个环境和一个日期。
- 原始记录按顺序包含 `callerId`、`serviceAddress`、`transactionCode`、`startTime`、`endTime`、`elapsedTime`、`responseStatus`、`responseCode`、`queryDate`、`globalFlowId`。
- 时间格式为 `yyyy-MM-dd HH:mm:ss`，耗时单位为 ms；响应状态固定 `Y/N/E`。
- 全局流水号精确匹配，调用方 ID 模糊匹配；交易码复用交易资产下拉；响应状态和响应码使用下拉框。
- 前端只允许选择今天至过去 39 天（含首尾共 40 天）；过期无数据按空结果处理。
- 非法记录直接忽略；首版不提供全量导出。

## M2：OBS 和实时日志追踪

### 外网实现边界

- 历史日志按运行环境、查询日期和全局流水号精确查询，支持日志预览和原始文件下载。
- 实时日志按运行环境和全局流水号查询；真实应用地址、端口、路径、参数和认证仍待内网协议确认。
- 历史日志和实时日志使用独立数据源接口；`default/local` profile 只加载明确标记的虚构日志源。
- 流水列表提供“日志追踪”入口并携带环境、日期和全局流水号，不实现复杂 TID 关联、异常分析或 AI 运维。

### M2 交互方案调整（2026-10-14 用户确认）

当前独立“日志追踪”页面只是外网技术原型，不作为最终交互验收基线。后续改为：

- 流水表格最左侧增加窄操作列，以日志/文件图标作为入口；不跳转新页面。
- 点击图标打开宽抽屉，保持流水列表和查询条件不丢失；不再为日志追踪配置独立菜单。
- 抽屉上半区左侧展示所选流水信息，右侧展示“相关日志文件”；下半区使用 CodeViewer 展示按全局流水号匹配的日志内容。
- 相关文件包括交易时间附近的已滚动日志，以及尚未落盘的 `.log.crn` 当前日志；每个文件独立下载。
- 已滚动应用日志按 20 MB 和准小时 rollover，基础命名规则为 `容器名-yyyyMMddHH.log`。不得根据该规则直接拼路径，应由 OBS/日志源列举真实对象后按时间邻近度筛选。
- 保留历史日志源、实时日志源及受控文件下载边界；前端独立日志页、跳转路由和当前日志菜单 SQL 需要在下一次开发中重构。

### M2 下一次开发顺序

1. 在开发环境执行并验证 `01_operation_flow_menu.sql`，重新登录后确认按钮权限、独立菜单清理和下载授权。
2. 使用外网模拟源完成浏览器人工验收：抽屉开闭、相关文件下载、空结果及截断提示。
3. 进入内网前确认 OBS 路径、容器映射、实时 HTTP 协议与文件筛选规则；再替换两个外部数据源实现。

### M2 内网待确认

- `serviceAddress` 到应用/容器名的准确映射来源，不能按连字符自行拆分。
- 同一小时超过 20 MB 时实际文件是否带序号、时间片或其它后缀；仅 `容器名-yyyyMMddHH.log` 无法区分同小时多个滚动文件。
- `.log.crn` 的完整文件名、存放位置，以及通过 OBS 还是应用实时 HTTP 接口列举和下载。
- “附近”文件的窗口：前一小时/当前小时/后一小时，还是按文件修改时间和数量上限计算。
- 匹配日志是否只返回命中行、命中前后上下文，或返回包含该流水号的完整交易片段；最大行数/字节数和截断提示。
- 跨整点、跨日、20 MB 提前滚动时的候选文件选择规则。

## M4：SOAP 在线调用

### 当前前端范围

- 目标地址控件仍默认展示所选交易已有的 `esfServiceAddress`，但静态响应模式不读取或调用该地址。
- 依据当前表单值生成无业务命名空间的临时 SOAP 1.1/1.2 Envelope；交易操作名优先使用 `esfServiceOperationName`。
- 点击发送时仅在前端生成固定 SOAP 成功响应并切换到响应页签，不发起任何网络请求；页面明确显示“静态响应模式”。
- 报文区只保留“请求报文”和“应用响应”两个互斥页签；进入页面或切换交易回到请求页签，发送时立即切换到响应页签。发送按钮与响应区同时显示 loading，完成前阻止重复发送。
- “一键调用”读取全部交易资产分页结果，在抽屉中接收一个容器地址，逐笔调用本系统模拟接口并展示进度、状态、响应码、耗时、流水号以及可展开的请求/响应 XML。
- `POST /api/intranet/operation/invocations/mock` 只读取交易资产详情并生成虚构结果，不创建 HttpClient、不访问目标地址；沿用 `intranet:operation:invoke:list` 权限。
- 不新增数据库对象、依赖、认证、证书、真实超时/重试、审计、脱敏或真实响应处理。
- 已验证浏览器直连被目标应用 CORS 策略拦截。正式链路应为前端调用本系统后端，再由后端 HttpClient/CXF 调用交易容器；具体实现等待内网协议确认。
- 用户已人工确认单笔静态响应、互斥请求/响应 Tab、按钮及响应 loading、一键批量进度和结果展示符合当前外网验收范围。

### 批量真实调用待确认

- “全部交易”是否包含草稿、开发中、已投产和已下线交易，演示版暂按资产列表全部结果处理。
- 每个交易的批量请求参数来源：固定样例、共享样例、字段默认值或人工配置。
- 顺序/并发数量、单笔和整体超时、停止、重试、失败继续策略及最大交易数量。
- 真实目标必须来自受控环境/容器清单，不能直接使用任意前端输入地址。

## M5：多环境响应对比

### 当前实现

- 新增独立页面 `pages/intranet/operation/compare`，路由 `/intranet/operation/compare`，权限 `intranet:operation:compare:list`。
- 页面复用交易资产、请求字段树及 operation 共享动态表单，同一套业务参数只生成一份请求 XML。
- 环境 A/B 来自 `GET /api/intranet/operation/comparisons/environments`；外网仅返回三个明确标记的虚构环境。
- `POST /api/intranet/operation/comparisons/mock` 返回两个模拟调用结果，包括响应状态、响应码、耗时、全局流水号、请求/响应 XML 和字段对比列表，不访问真实容器。
- 点击“开始对比”后立即打开宽抽屉并展示调用 loading；抽屉内并排展示两个环境的摘要与响应报文，字段表支持一致、值不同、仅 A、仅 B，高亮差异并支持“仅查看差异”。主页面只保留对比配置、统一业务参数和统一请求报文。
- 已修正结果摘要 `Descriptions` 的列跨度配置，避免 Ant Design 报出一行 `span` 总和与 `column` 不一致的警告。
- 菜单脚本新增“多环境响应对比”，开发验证脚本和回退脚本已同步。

### 待确认与验收

- 执行菜单脚本并重新登录，确认独立菜单、动态路由和 `intranet:operation:compare:list` 权限。
- 浏览器验证交易切换、嵌套字段、环境不可相同、抽屉 loading/关闭限制、双响应布局、差异高亮和仅差异开关；确认控制台不再出现 `Descriptions` 列跨度警告。
- 动态流水号、时间戳、耗时等字段是否忽略尚未确认；模拟结果当前如实列为差异。
- 数组顺序、重复节点、空值、类型、数字精度、日期格式和 XML 命名空间规范化规则待确认，当前不实现通用 XML 规则引擎。
- 真实环境最终应复用 M4 后端 SOAP 调用服务分别调用 A/B；当前模拟接口只预留契约。
