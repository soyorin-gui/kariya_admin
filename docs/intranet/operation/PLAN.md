## M1：多环境 Redis 流水查询

### 已确认契约

- Redis Key 为 `yyyy-MM-dd`，每个日期对应一个 List；一次只查询一个环境和一个日期。
- 原始记录按顺序包含 `callerId`、`serviceAddress`、`transactionCode`、`startTime`、`endTime`、`elapsedTime`、`responseStatus`、`responseCode`、`queryDate`、`globalFlowId`。
- 时间格式为 `yyyy-MM-dd HH:mm:ss`，耗时单位为 ms；响应状态固定 `Y/N/E`。
- 全局流水号精确匹配，调用方 ID 模糊匹配；交易码复用交易资产下拉；响应状态和响应码使用下拉框。
- 前端只允许选择今天至过去 39 天（含首尾共 40 天）；过期无数据按空结果处理。
- 非法记录直接忽略；首版不提供全量导出。

## M2：OBS 和实时日志追踪

### 外网实现边界

- 历史日志按运行环境、查询日期和全局流水号精确查询，支持日志预览和原始文件下载。
- 实时日志按运行环境和全局流水号查询；真实应用地址、端口、路径、参数和认证仍待内网协议确认。
- 历史日志和实时日志使用独立数据源接口；`default/local` profile 只加载明确标记的虚构日志源。
- 流水列表提供“日志追踪”入口并携带环境、日期和全局流水号，不实现复杂 TID 关联、异常分析或 AI 运维。

### M2 交互方案调整（2026-10-14 用户确认）

当前独立“日志追踪”页面只是外网技术原型，不作为最终交互验收基线。后续改为：

- 流水表格最左侧增加窄操作列，以日志/文件图标作为入口；不跳转新页面。
- 点击图标打开宽抽屉，保持流水列表和查询条件不丢失；不再为日志追踪配置独立菜单。
- 抽屉上半区左侧展示所选流水信息，右侧展示“相关日志文件”；下半区使用 CodeViewer 展示按全局流水号匹配的日志内容。
- 相关文件包括交易时间附近的已滚动日志，以及尚未落盘的 `.log.crn` 当前日志；每个文件独立下载。
- 已滚动应用日志按 20 MB 和准小时 rollover，基础命名规则为 `容器名-yyyyMMddHH.log`。不得根据该规则直接拼路径，应由 OBS/日志源列举真实对象后按时间邻近度筛选。
- 保留历史日志源、实时日志源及受控文件下载边界；前端独立日志页、跳转路由和当前日志菜单 SQL 需要在下一次开发中重构。

### M2 下一次开发顺序

1. 将 `pages/intranet/operation/logs/index.tsx` 的可复用逻辑下沉为流水页内 `FlowLogDrawer`，删除独立页面跳转。
2. 将流水页当前右侧文字操作改为最左侧图标操作，传入完整所选流水上下文。
3. 后端提供一次聚合的日志上下文响应：流水概要、匹配日志文本、相关文件列表、截断/警告信息。
4. 历史源负责 OBS 已滚动文件；实时源负责 `.log.crn` 当前文件。下载统一使用后端签发的受控文件标识，不接受任意对象路径。
5. 调整菜单 SQL：删除独立“日志追踪”菜单，将日志查看与下载权限作为“流水查询”的按钮权限。
6. 使用外网模拟源完成抽屉布局与交互验证；再进入内网校准 OBS 路径、容器映射和实时 HTTP 协议。

### M2 内网待确认

- `serviceAddress` 到应用/容器名的准确映射来源，不能按连字符自行拆分。
- 同一小时超过 20 MB 时实际文件是否带序号、时间片或其它后缀；仅 `容器名-yyyyMMddHH.log` 无法区分同小时多个滚动文件。
- `.log.crn` 的完整文件名、存放位置，以及通过 OBS 还是应用实时 HTTP 接口列举和下载。
- “附近”文件的窗口：前一小时/当前小时/后一小时，还是按文件修改时间和数量上限计算。
- 匹配日志是否只返回命中行、命中前后上下文，或返回包含该流水号的完整交易片段；最大行数/字节数和截断提示。
- 跨整点、跨日、20 MB 提前滚动时的候选文件选择规则。

## 实施边界

- 新代码继续放在 intranet 独立业务包内，建议后端使用 `backend/src/main/java/org/lbl/intranet/operation/`，前端使用 `frontend/src/pages/intranet/operation/`；最终子目录在 M0 结合动态路由事实确认。
- 保持现有 UI 风格、Ant Design 组件、请求封装、权限与代码规范，不创建子工程或重复通用封装。
- 可以复用交易资产既有只读 API/Service；若现有契约不足，不得直接修改，必须先提出最小扩展方案并等待用户批准。
- `lineage` 模块当前受保护；运行监控不得改变其数据库结构、字段、业务逻辑或 API 语义。
- 真实内网地址、账号、令牌、证书、日志、交易流水和可识别样例不得进入个人 Git 仓库；示例必须脱敏并标注虚构。
- M1-M6 的外部系统定义、权限、审计、超时、数据保留和验收标准均以用户确认结果为准。

- “OBS” 的具体产品/协议和日志接入方式尚未确认。

- SOAP 调用的服务清单、认证、证书和网络边界尚未确认。
- 响应差异的规范化和忽略规则尚未确认；不应先写通用比较引擎。
